# 0 · The idea

**For anyone.** No code yet.

## The idea in one line

Things that never touch, talking only through a gate, and everything that happens written down where it can't be erased.

## A picture

Imagine a row of houses. Each house has its own things inside, and nobody can walk into someone else's house.

- To say something to another house, you write a **note** and drop it in the **post box** at the end of the street.
- The post box has a **keeper**. The keeper reads every note's envelope: is it from a real house? Is it going to a real
  house? Is it the right kind of note? If not, the keeper **does not deliver it**, and writes down why.
- The keeper also writes every delivered note into a big **notebook**. Each page is stamped with a code made from the page
  before it, so if anyone tears out or changes a page, the codes stop matching and everyone can tell.
- When something is **missing** (a house that should answer, but doesn't), the keeper writes that down too, with how
  much it matters. Missing things are not ignored. They are written down until someone fixes them.

That is Emerge:

| In the street | In Emerge | Why it helps |
|---|---|---|
| A house | a **component** (or a compartment) | Nothing can break it from outside |
| A note | an **event** (a signal) | Every conversation can be seen |
| The keeper | the **gate** | Wrong notes never arrive |
| The notebook | the **ledger** | You can always prove what happened |
| A missing thing written down | a **gap** | Problems can't hide |

## Try it, with no computer

1. Three friends are three houses. Each keeps a number on a piece of paper: start at 0.
2. A fourth friend is the keeper, with a notebook.
3. Rule for one house: "my number can never go below zero."
4. Pass notes through the keeper: "House A: add 2." "House A: take 5."
5. The keeper delivers the first note and writes it down. The house refuses the second one, because it would break its
   rule, and the keeper writes down *that* too.

You have just run an Emerge program.

## Why it matters

Big programs fail because parts reach into each other, things go wrong silently, and nobody can say what really happened.
These three rules stop all three, at every size: a game, a website, an operating system.
